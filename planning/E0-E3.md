# E0–E3 Execution Plan

## E0 — Contract and boundary freeze

**Goal:** allow parallel implementation without conflicting assumptions.

### Deliverables

- selected application stack and repository layout,
- canonical `ExecutionEvent` contract,
- `Incident` and failure-oracle contracts,
- execution graph node and edge contract,
- Replay Capsule v1 contract,
- replay lifecycle and result contract,
- single-intervention contract,
- Replay Diff contract,
- System Pack v1 interface,
- isolation and reset contracts,
- golden demo configuration and fixtures, and
- ownership for each implementation workstream.

### Exit criterion

Each contract has a version, required fields, validation behavior, and at least one golden example. Three implementers can consume the contracts without inventing new cross-workstream fields or changing the product scope.

## E1 — Capture to incident trace

**Goal:** turn one real demo request into a stable incident graph and timeline.

### Deliverables

- Gateway–Checkout–Payment–Ledger demo path,
- controlled latency, timeout, retry, and duplicate-effect behavior,
- capture hooks and event normalizer,
- normalized event persistence,
- duplicate-effect failure oracle,
- incident creation and inspection API,
- execution graph construction, and
- ordered incident timeline.

### Exit criterion

From a clean reset, the golden request repeatedly creates one inspectable incident containing the expected timeout, retry, two payment attempts, two ledger effects, graph relationships, and true oracle evidence.

## E2 — Capsule to safe baseline replay

**Goal:** reproduce the incident without real external side effects.

### Deliverables

- Replay Capsule compiler,
- schema and integrity validation,
- fixture and System Pack resolution,
- isolated replay runtime,
- payment dependency simulator,
- replay-only ledger storage,
- default-deny network and credential policy,
- baseline replay event capture,
- isolation evidence, and
- reproducibility evaluation.

### Exit criterion

A valid capsule reaches `REPRODUCED`, records the expected structural and oracle evidence, and proves that all side effects remained inside replay. Unsafe or incomplete capsules reach `BLOCKED` with a specific reason.

## E3 — What-if replay and differential

**Goal:** show how execution changes when one approved condition changes.

### Deliverables

- latency intervention validation and application,
- zero-intervention versus one-intervention enforcement,
- what-if replay event capture,
- event alignment,
- Replay Diff generation,
- first meaningful divergence detection,
- effect-count and oracle comparison,
- evidence-backed explanation, and
- integrated Command Center workflow.

### Exit criterion

Changing only payment latency from `350 ms` to `50 ms` removes the timeout, retry, and duplicate effect; the UI highlights the expected first divergence and shows the supporting timelines and isolation evidence.

## Cross-epoch rule

An epoch does not begin because its planned time arrived. It begins when the previous exit criterion passes. Any contract-breaking discovery returns to E0 for explicit team agreement and versioning.
